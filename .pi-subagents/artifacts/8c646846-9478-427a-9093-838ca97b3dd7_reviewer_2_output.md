- **Blocker:** The projection tail does not verify `MessageEvent.last_event_id()` against the decoded frame cursor. It decodes `SessionProjectionFrame` and immediately classifies only `frame.cursor` (`daemon.rs:3709-3738`). The daemon uses SSE `id` as the reconnect acknowledgement, so disagreement between the SSE ID and body cursor can make the UI apply one position while the next reconnect resumes from another. This directly misses the plan’s required last-event-ID/frame-cursor verification.
- **Blocker:** Authoritative folded projection state is decoded permissively. `active_turn`, `last_turn_finished`, and `model_rerouted` use `.ok()` and session filtering, while pending permissions use `filter_map` (`daemon.rs:1998-2009`). Malformed or incorrectly scoped authoritative state is silently discarded and the snapshot is still installed, rather than rejecting/refetching the projection. This does not meet strict response-decode behavior.
- **Note:** The new snapshot request interpolates the session ID directly into `/v1/sessions/{id}` (`daemon.rs:3387-3388`), as do existing hydration/restore paths (`daemon.rs:3917-3920, 6238-6241`). Query parameters are encoded correctly, and current daemon IDs are UUIDs, but the path is not encoded or locally UUID-validated.
