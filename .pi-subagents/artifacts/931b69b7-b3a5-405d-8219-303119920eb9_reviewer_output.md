# Dynamic Island manual acceptance checklist

## 1. Fixture and host gating

Prepare the daemon with at least four sessions across two projects:

- A focused session with a distinctive title.
- A newer background session.
- An older background session.
- A zero-turn session.
- Include metadata suitable for queries: project `ocean-surface`, cwd containing `src/app.rs`, branch `main`, and an origin-prefixed title such as `[WEB] North star`.

Verify:

- **Tauri:** centered Island chip is present instead of the labeled Sessions button.
- **Browser/PWA/extension:** Island is absent; Sessions remains present.
- **Browser/PWA:** `⌘P`/`Ctrl+P` retains browser print behavior rather than opening Island.

Expected closed chip:

- With focus: aqua dot, focused title, optional project, and count of nonfocused recent sessions.
- Without focus: `Ocean · no session` plus the current `0 recent`/recent count presentation.
- Long title/project truncates rather than overlapping header controls.
- Dragging unused header/brand space moves the window; dragging the chip does not.

Evidence: `island.rs:376-437`, `app.rs:1019-1053`.

## 2. Mouse flows

1. **Click closed chip**
   - Overlay opens in Browse mode.
   - Scrim covers the window below the chip.
   - Search input receives focus, but existing text is not selected in Browse mode.
   - Query is cleared and first result selected.
   - Sessions/projects are refreshed.
   - Focused session appears first, followed by newest sessions.
   - Rows show title plus available project/path/branch/origin/time/turn metadata.
   - Focused row shows `Focused`.

2. **Click chip while open**
   - Overlay closes.
   - Focus returns to the previously focused connected element, normally the chip for a mouse-opened flow.

3. **Reopen, then click scrim**
   - Overlay closes without switching sessions.
   - Prior focus is restored.

4. **Reopen, click a nonfocused row**
   - Overlay closes.
   - Center transcript changes to that session.
   - Reopening shows the newly focused session first with `Focused`.
   - Former session remains in the catalogue.

5. **Click inside search/results**
   - Must not trigger scrim closure.

Evidence: `island.rs:275-314`, `island.rs:418-547`.

## 3. Keyboard and focus flows

Test `⌘P` on macOS and `Ctrl+P` where applicable from each location:

- Composer textarea
- Workspace control/content
- Header control
- Transcript/content

Expected each time:

1. Island opens/replaces sibling overlays in Search mode.
2. Search input receives focus on the next animation frame.
3. Existing query is selected when reopening Search while already open.
4. Opening from Closed clears query and resets selection to row 1.
5. IME composition is not interrupted.

Then test:

- `ArrowDown`: selects next result, wrapping last → first.
- `ArrowUp`: selects previous result, wrapping first → last.
- `Enter`: calls the normal session switch path, closes Island, and changes transcript.
- `Escape`: closes only Island, prevents bubbling, and restores prior focus.
- `Tab` and `Shift+Tab`: current implementation keeps focus on the Island input; focus must not escape behind the modal.
- With no matches, arrows/Enter do nothing and `No matching sessions` remains visible.
- Repeated arrows through more rows than fit onscreen should keep the selected highlight visible. A disappearing highlight indicates the missing scroll-follow risk.

Evidence: `app.rs:774-828`, `island.rs:292-374`, `island.rs:478-480`.

## 4. Search acceptance

Enter each query separately and confirm the intended session remains visible:

- `north star` — title match; title should outrank metadata-only matches.
- `project:ocean-surface` — literal project document match.
- `src/app.rs` — cwd/path.
- `main` — exact project or branch; exact project outranks fuzzy title.
- `tauri` or `web` — parsed origin metadata.
- `recent` — recent-state text.
- `focused` — focused-state text.
- `0 turns` — zero-turn session remains searchable.
- A fuzzy subsequence such as `nrth str` — matching follows the shared `⌘K` scorer.
- A nonsense query — visible `No matching sessions`.

Search mode is capped at 20 results. Empty Browse mode retains the full catalogue inside a scrollable results region.

Evidence: `island.rs:126-203`, `island.rs:267-273`, tests at `island.rs:634-731`.

## 5. Width and workspace matrix

Reset workspace width to its default `520px` before checking computed values. If resized, use `W = computed --workspace-w`.

| Viewport | Workspace closed | Workspace open | Expected chip content |
|---|---|---|---|
| **720px** | Chip `210px`; popover `560px` | Workspace overlays beneath Island; Island geometry unchanged | Dot + title only; project, separators, count hidden |
| **840px** | Chip `240px`; popover `560px` | Workspace overlays beneath Island; Island geometry unchanged | Dot + title + recent count; project/separators hidden |
| **900px** | Chip `300px`; popover `560px` | Split layout. Default `W=520`: remaining content ≈`380px`, chip ≈`159.6px`, popover `348px` | Dot + title + count; project/separators hidden; brand hidden while workspace open |
| **1280px** | Chip `360px`; popover `560px` | Split layout. Default `W=520`: remaining content ≈`760px`, chip ≈`334.4px`, popover `560px` | Full title/project/count metadata |

General workspace-open formulas at widths ≥900px:

- Chip: active breakpoint percentage of the remaining header width.
- Popover: `min(560px, viewport - W - 32px)`.
- Popover right edge: `W + 16px`, centered over the remaining content column.
- At widths below 900px, workspace is an overlay and must not shift Island geometry.

At every width verify:

- Popover top is `64px`.
- Horizontal safe inset is at least `16px`.
- No traffic-light, brand, runtime, overflow, or workspace-toggle overlap.
- Workspace remains beneath scrim/popover.
- Results scroll vertically; the whole page does not acquire horizontal overflow.

Evidence: `styles/island.css:4-129`, `styles/island.css:265-326`, `styles/workspace.css:17-75`.

## 6. Overlay priority

Exercise these exact sequences:

1. Open Sessions/Rooms/Council, then press `⌘P`.
   - Prior surface closes; Island alone remains.

2. Open Island, then invoke Sessions/Rooms/Council.
   - Island closes; latest explicitly opened surface remains.

3. Open Island, then press `⌘K`.
   - Island closes and command palette alone appears.
   - Palette visually wins at z-index `1100`.

4. Use `⌘K`, search `Search Ocean…`, press Enter.
   - Palette closes; Island Search opens and input is focused.

5. Press `Escape` against each topmost surface.
   - One Escape closes exactly one surface.
   - Global priority is palette → Council → Island → Rooms → Sessions → Deck.

Layering expectation:

- Workspace `50`
- Deck `60`
- Sessions/Rooms `100`
- Island scrim `120`, popover `121`, chip/host `122`
- Council `1000`
- Palette `1100`

Evidence: `app.rs:340-362`, `app.rs:804-827`, `styles/island.css:23-35,95-120`, `styles/deck.css:560-580`.

## Likely failure signatures

- `⌘P` opens print in Tauri, or is intercepted in browser/PWA.
- Island appears in browser/extension or labeled Sessions disappears there.
- Chip overlaps traffic lights/runtime controls or cannot be clicked because it acts as a drag region.
- At 900px with workspace open, popover remains viewport-centered, extends beneath the workspace, or exceeds the remaining `348px` default width.
- Workspace paints above Island scrim/popover.
- Browse click does not focus input, or Search open does not select existing input text.
- Escape closes multiple surfaces or fails to restore composer/header focus.
- Arrow selection fails to wrap, switches the wrong row, or moves offscreen without scrolling.
- Enter/click closes Island but transcript remains on the old session.
- Former focused session disappears after switching.
- `[WEB]` remains in the visible title instead of appearing as `web` metadata.
- Zero-turn session is absent or `0 turns` cannot find it.
- Query reopening from Closed retains stale text instead of resetting.
- More than 20 results appear in Search mode.
- `Tab` escapes behind the modal despite `aria-modal="true"`.
