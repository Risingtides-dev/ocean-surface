## Review

- **Correct:** Camera follow/FOV interpolation updates projection each frame (`src/game/Arwing.tsx:61-72`); terminal states switch the Canvas to demand rendering (`src/game/Game.tsx:367-377`); R3F declarative objects should dispose on unmount.
- **Blocker:** `src/game/Terrain.tsx:21-28, 61-80` — shader tile coordinates use `position.y + uTileZ`, but the plane is rotated `-PI/2`, so world Z is `uTileZ - position.y`. Adjacent wrapped tiles therefore evaluate different shader coordinates at the same world-space edge, producing height/grid seams. Use the rotated world-Z sign consistently.
- **High:** `src/game/Game.tsx:184-216` — visibility change only clears input; it does not pause the simulation. Hidden/background tabs can continue advancing distance, enemy expiration, and damage. No explicit pause state exists, and simulation delta is not capped on resume.
- **High:** `src/game/Arwing.tsx:33-95` — the fuselage cones are rotated toward `+Z`, while player projectiles travel `-Z`; plume meshes and lights are also at `+Z`. The aircraft silhouette/engine lighting is visually reversed relative to its firing trajectory.
- **High:** `src/game/Game.tsx:377-379`, `src/game/Enemy.tsx:75-116`, `src/game/Laser.tsx:54-63` — every enemy and projectile can add a dynamic point light, with no active-light cap or pooling. Combined with bloom and mobile DPR up to `1.75`, this can cause substantial mobile GPU cost.
- **Medium:** `src/game/Game.tsx:398-424` — projectile collision checks sample positions only; there is no swept segment test. At low frame rates, 76-units/sec player lasers can jump across an enemy/player collision volume and miss.
- **Medium:** `src/game/Laser.tsx:15-31`, `src/game/Enemy.tsx:120-170` — each laser/enemy instance allocates separate geometry, material, and (for most instances) a point light. R3F cleanup prevents an obvious permanent leak, but repeated spawn/unmount allocation and disposal creates avoidable GC/GPU churn. Pool or instance projectiles and reuse shared resources.
- **Medium:** `src/game/Game.tsx:312-326` — win/loss stops rendering but leaves remaining enemy and laser components mounted, retaining their meshes/materials/lights until redeploy or page unmount. Clear active entities on terminal state.
- **Medium:** `src/game/SceneEffects.tsx:5-14` — composer multisampling is explicitly disabled and no FXAA/SMAA is present. Low-poly silhouettes can alias noticeably, especially on high-DPR mobile displays.
- **Low:** `src/styles.css:35-48` — mobile touch controls and the teammate panel both occupy the lower-right region, with no responsive reservation; they can overlap on narrow portrait screens.
- **Note:** `src/game/Game.tsx:377-379` caps DPR at `1.75` but has no device/performance-tier adjustment. Consider a lower mobile cap and dynamic quality reduction for bloom/lights.
