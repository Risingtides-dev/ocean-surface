## Review
- Correct: `Session.persistence_revision` is serde-defaulted for legacy JSON and advances on a clone only after the atomic rename succeeds (`crates/ocean-agent/src/session/mod.rs:364-400`).
- Correct: Runtime `TurnCheckpoint` is filtered, persisted, and replaced by `PersistenceCheckpoint` only after a successful save (`crates/ocean-agent/src/lib.rs:1725-1793`).
- Correct: Cancellation during a tool batch produces ordered conservative results before checkpointing; failed saves do not publish a checkpoint.
- Blocker: Checkpoints indiscriminately set `checkpoint_seq` to the journal’s current `latest` sequence (`crates/ocean-daemon/src/session_projection.rs:343-359`). Thus events not represented by the saved transcript are incorrectly declared subsumed. For example, a turn can stream partial text and then fail without a valid-round save (`crates/ocean-agent/src/lib.rs:1804-1820`). The next accepted-user save advances the checkpoint past that failed partial output, permanently omitting it from fresh snapshots. The inactive-session alignment fallback has the same issue by setting `checkpoint_seq = latest` (`crates/ocean-daemon/src/session_projection.rs:385-390`). This is concrete projection data loss.
- Blocker: Pre-stream failover emits `ModelRerouted`, then the fallback path re-saves the already-durable accepted-user row and emits another checkpoint (`crates/ocean-agent/src/lib.rs:912-947,1547-1569`). Because reroutes are neither in session JSON nor folded state, that checkpoint removes the reroute from a fresh snapshot. It also contradicts the stated reuse-without-resave boundary.
- Note: No end-to-end tests exercise failed partial output followed by another save, cancellation followed by resume, or pre-stream failover checkpoint ordering. Existing projection unit tests therefore do not catch these losses.
