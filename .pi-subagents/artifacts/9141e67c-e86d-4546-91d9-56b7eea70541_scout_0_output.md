pub struct PendingPermission {
    pub permission_id: String,

It is daemon-backed through `/v1/events`, but the client explicitly filters that global control stream to the **focused** session (`daemon.rs:1933-1996`). The current Island already owns modal focus restoration, query/selection, combobox/listbox semantics, Escape/Tab/arrows, and session switching (`island.rs:285-402, 436-580`). `app.rs` owns mode and mutual exclusion (`app.rs:337-362`) and already mirrors `pending_permissions.len()` to the dock badge (`app.rs:709-718`).

## Architecture

### What can be implemented honestly now
A smallest safe read-only attention popdown can display **pending permission attention for the currently focused session only**. It may show a compact warning/count in the Island chip and a read-only expanded card containing tool, reason, and safely bounded args summary. It must say “permission required” or “needs your attention,” not imply background/global coverage. Keep the existing composer-adjacent `PermissionPrompts` as the sole Approve/Deny surface (`components.rs:1524-1588`). No call to `decide_permission`, no reply composer, no new daemon authority.

A useful pure seam in `island.rs` would be an `IslandAttentionItem` (or extend `IslandResult` with an attention variant) derived from `pending_permissions`, with a stable key (`permission_id`) and explicit `session_id`. Do not overload timestamp-derived `IslandPriority`: it means focused/recent/background, not urgency.

### Missing contracts (block true cross-session Phase 2)
The proposed `WorkAttentionItem` snapshot/stream in both Island docs does not exist. Missing daemon-owned fields/endpoints are: stable item id, kind, optional session id, title/detail, authoritative state (`Idle|Running|NeedsHuman|Failed|Complete`), updated time, priority, initial snapshot/replay, and lifecycle/removal semantics. Also missing:

- Cross-session permission observation: current `/v1/events` subscriber drops non-focused sessions.
- Cross-session run/failure/completion truth: session catalogue timestamps cannot provide it.
- Session/project display metadata on attention items, or a guaranteed join against `session_list`.
- Ordering/deduplication/reconnect contract and event-name subscription contract (named SSE events are silently dropped unless subscribed; `daemon.rs:687-714`).
- Read/acknowledged semantics, if a card can be dismissed.

Do not create a Tauri-local attention store or open one SSE pair per background session; browser connection limits are already documented (`daemon.rs:35-40`). The daemon should supply one snapshot plus one aggregate stream, ideally shared-core HTTP/SSE rather than a Tauri command.

### Smallest safe vertical slice
1. In `island.rs`, derive a read-only focused permission attention view from `daemon.pending_permissions`; add pure tests for empty, ordered/deduped display, session mismatch filtering, and safe empty reason/args rendering.
2. Preserve `IslandMode::{Closed,Browse,Search}`. Render the attention card at the top of the existing popover (before session search/results), only when pending data exists. Do not introduce another overlay.
3. Chip: change dot/count/accessible label conditionally when pending count > 0; no animation. Use `--warn`/`--warn-soft`, not accent (design doc permission-wait semantics).
4. Card: read-only `role="status"` or labelled region with heading “Permission required,” tool, concise reason, optional truncated/pre-wrapped args, and guidance such as “Review in the session below.” It must contain no Approve, Deny, reply input, or dismiss action.
5. Keep click/`Cmd+P` behavior, session rows, `switch_session`, `PermissionPrompts`, dock badge, and web/extension gating unchanged. If the card is only focused-session data, clicking it need not mutate or navigate.
6. Add selectors only to `styles/island.css`; colors remain token-only. Reuse the single elevated popover and plain-row vocabulary—no nested elevated card, pill text control, decorative pulse, or new stylesheet.
7. Validate with one pending permission arriving/removing via daemon SSE, zero/multiple permissions, keyboard-only use, screen reader announcement, narrow/wide Tauri, and no web/extension visual change.

### Accessibility/state requirements
- Keep one modal dialog and current focus capture/restore; do not create a nested dialog.
- Update chip `aria-label` with exact pending count and `aria-expanded`; avoid relying on color/dot alone.
- Permission arrival while closed should be announced by a restrained `aria-live="polite"` status; avoid repeatedly announcing on unrelated reactive updates.
- Expanded card must have a programmatic heading/label; tool/args should remain readable, wrap safely, and not expose raw unbounded payload in compact chrome.
- Escape closes exactly one surface; IME guards remain; focus returns to prior connected element/chip.
- If attention is inserted ahead of listbox results, it is not a listbox `option` and must not disturb `aria-activedescendant`, selected index, Arrow/Enter behavior, or result IDs.
- Respect `prefers-reduced-motion`; this slice needs no new motion.
- State clears reactively when `permission_decision` arrives. Do not add local dismiss/read state.
