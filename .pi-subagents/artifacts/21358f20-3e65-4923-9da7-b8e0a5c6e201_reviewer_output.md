The generation is checked before `rehydrate_transcript(...).await` (`crates/ocean-surface-ui/src/daemon.rs:1814-1849`) but not again before creating and installing the source (`crates/ocean-surface-ui/src/daemon.rs:1851-1870`). If a session switch occurs during that await, `connect()` advances the generation and installs the new session stream, then the resumed stale task calls `replace_event_source`, closes that new stream, and stores its old-session stream. This is not self-healing: the current loop ignores the close-generated subscription errors (`crates/ocean-surface-ui/src/daemon.rs:1904-1912`) and can remain waiting on the explicitly closed source, while the stale stream is idle and generation-gated. Re-check `sse_generation == generation` immediately after rehydration/before `EventSource::new` (or make installation generation-conditional) so a stale task cannot take ownership of the slot.
