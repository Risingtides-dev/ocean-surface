# Implementation Plan

## Goal
Add a daemon-owned, session-scoped transcript projection cursor aligned with atomic session checkpoints, without exposing transcript content through Observatory or mixing `SurfacePatch` into the content cursor.

## Current-State Diagnosis

At the stated `origin/main` revision `d87d7d9`:

- `ocean-agent/src/session/mod.rs` persists complete `Session` JSON atomically using temp-file write, `fsync`, and rename, but has only timestamp-based `updated_ms`, not a monotonic persistence revision.
- `ocean-agent/src/lib.rs` saves:
  1. the accepted user message before provider execution;
  2. completed provider rounds on `AgentEvent::TurnCheckpoint`;
  3. the final capped transcript.
- `TurnCheckpoint` contains provider-valid assistant/tool-result deltas, but the daemon intentionally filters it from `/v1/agent/events`.
- `/v1/agent/sessions/{id}` exposes metadata and prompt-derived turns, not full assistant/thinking/tool content.
- `/v1/sessions/{id}` exposes persisted transcript, tool context, and raw messages, but has no cursor or reconnect consistency contract.
- `/v1/agent/events` is a transient global SSE bus with a 2,048-event/32 MiB replay ring. It cannot guarantee recovery for a complete session transcript.
- Components and browser activity exist only as transient events. Active turns and pending permissions are derived from daemon registries.
- `SurfacePatch` currently travels through the live agent-event rail and is stamped with client-ledger envelopes; the daemon explicitly is not its merge authority.

The requested `context.md` was absent, so the route names below are a concrete recommended contract rather than confirmation of names from that missing document.

## Proposed Wire Contract

### Routes

Add these daemon routes:

- `POST /v1/agent/sessions/{id}/projection/attach`
  - Applies the same optional `cwd`/`workspace` scope check as session detail.
  - Returns a full snapshot, an opaque content cursor, and a 60-second lease.
- `GET /v1/agent/sessions/{id}/projection/changes?lease_id=<uuid>&after=<cursor>`
  - Returns ordered changes after the cursor and renews the lease.
  - Returns an explicit reset response if the cursor or lease is unusable.
- `DELETE /v1/agent/sessions/{id}/projection/attach/{lease_id}`
  - Best-effort early release; lease expiry remains authoritative cleanup.

Recommended response shapes:

```json
{
  "kind": "snapshot",
  "schema_version": 1,
  "lease": {
    "id": "uuid",
    "expires_at": "RFC3339"
  },
  "cursor": "epoch:sequence",
  "snapshot": {
    "session": {
      "id": "uuid",
      "title": "...",
      "cwd": "...",
      "created_at": "...",
      "updated_at": "...",
      "client_type": "surface-web",
      "persistence_revision": 17
    },
    "messages": [],
    "active_turn": null,
    "pending_permissions": [],
    "components": [],
    "browser": {
      "active": false
    },
    "transient": null
  }
}
```

```json
{
  "kind": "changes",
  "lease": {
    "id": "uuid",
    "expires_at": "RFC3339"
  },
  "from": "epoch:sequence",
  "cursor": "epoch:sequence",
  "changes": [
    {
      "cursor": "epoch:sequence",
      "change": {
        "type": "assistant_text_delta",
        "turn_id": "uuid",
        "delta": "..."
      }
    }
  ]
}
```

Unrecoverable cursors return HTTP `409` with a fresh snapshot rather than silently skipping data:

```json
{
  "kind": "reset_required",
  "reason": "lease_expired",
  "lease": {
    "id": "new-uuid",
    "expires_at": "RFC3339"
  },
  "cursor": "new-epoch:new-sequence",
  "snapshot": {}
}
```

Reset reasons should be a closed enum:

- `malformed_cursor`
- `epoch_mismatch`
- `future_cursor`
- `cursor_evicted`
- `lease_expired`
- `lease_mismatch`
- `journal_pressure`

### Content Schema

Add SDK-owned projection types:

- `SessionProjectionCursor`
- `SessionProjectionLease`
- `SessionProjectionSnapshot`
- `SessionProjectionMessage`
- `SessionProjectionContent`
- `SessionProjectionRuntimeState`
- `SessionProjectionComponent`
- `SessionProjectionChange`
- `SessionProjectionChangeEnvelope`
- `SessionProjectionAttachResponse`
- `SessionProjectionChangesResponse`
- `SessionProjectionResetReason`

`SessionProjectionContent` should explicitly model:

- text;
- completed thinking;
- image metadata without base64 data;
- tool calls with call ID, name, and arguments;
- tool results with call ID, name, error status, and output.

Do not expose provider-private raw structures as the new public projection schema.

`SessionProjectionChange` should include:

- `turn_started`
- `assistant_text_delta`
- `thinking_delta`
- `tool_call_started`
- `tool_call_chunk`
- `tool_call_finished`
- `checkpoint`
- `permission_upsert`
- `permission_remove`
- `component_upsert`
- `component_remove`
- `browser_activity`
- `turn_finished`

A `checkpoint` contains the complete normalized durable message vector and `persistence_revision`; it replaces all earlier transcript/transient content through that revision.

1. **Write protocol tests before implementing the SDK types**

   - Acceptance:
     - Tests demonstrate stable `snake_case` tags and exact snapshot/reset shapes.
     - Existing `AgentTurnEvent` serde tests remain unchanged.

2. **Add monotonic session persistence revisions**
   - File: `crates/ocean-agent/src/session/mod.rs`
   - Changes:
     - Add `persistence_revision: u64` to `Session` with `#[serde(default)]`.
     - Add the same field to the projected `SessionDetail` in `crates/ocean-core/src/lib.rs`.
     - Replace direct persistence with a commit helper that:
       1. clones the candidate session;
       2. increments the revision with checked arithmetic;
       3. stamps `updated_ms`;
       4. atomically writes, fsyncs, and renames the candidate;
       5. updates the caller’s in-memory session only after success.
     - Preserve duplicate-file healing and workspace bucket behavior.
   - Acceptance:
     - Legacy JSON without a revision loads as revision `0`.
     - First successful rewrite becomes revision `1`.
     - Multiple saves within one millisecond still have distinct revisions.
     - A failed write changes neither the in-memory nor durable revision.

3. **Publish committed checkpoint information only after persistence succeeds**
   - Files:
     - `crates/ocean-runtime/src/types.rs`
     - `crates/ocean-agent/src/lib.rs`
   - Changes:
     - Extend internal `AgentEvent::TurnCheckpoint` with optional committed metadata, such as:
       - `persistence_revision: Option<u64>`
       - `persisted_messages: Option<Vec<Message>>`
     - Runtime-emitted checkpoints set both to `None`.
     - In `ocean-agent`, special-case checkpoint forwarding:
       1. consume the runtime delta;
       2. append it to the valid prefix;
       3. persist successfully;
       4. forward the checkpoint to the daemon with the committed revision and complete capped message snapshot.
     - Emit the same committed checkpoint form after accepted-user persistence and final persistence.
     - Never forward a committed checkpoint when persistence fails.
   - Acceptance:
     - The accepted user row becomes observable before provider side effects.
     - Assistant tool calls and ordered results appear together.
     - Completed thinking appears in the committed snapshot.
     - In-progress thinking remains only a transient delta.
     - Failed or cancelled incomplete rounds do not become durable.

4. **Implement the bounded content journal test-first**
   - New file: `crates/ocean-daemon/src/session_projection.rs`
   - Changes:
     - Add `SessionProjectionJournal`, backed by one `Arc<std::sync::Mutex<JournalState>>`.
     - State contains:
       - daemon-epoch UUID;
       - next global `u64` sequence;
       - `VecDeque` of content changes;
       - exact serialized-byte total;
       - latest per-session durable checkpoint;
       - folded per-session transient/runtime state;
       - attach leases keyed by UUID.
     - Default journal limit: `256 * 1024 * 1024`.
     - Configuration: `OCEAN_SESSION_PROJECTION_JOURNAL_BYTES`; invalid or zero values fall back to 256 MiB.
     - Lease duration: fixed 60 seconds, with an injectable clock for tests.
     - Count serialized change-envelope bytes, using saturating arithmetic.
   - Acceptance:
     - Global bytes never exceed the configured limit.
     - Cross-session changes share the global cap but never cross session filtering.
     - An individually oversized change is not retained and forces affected cursors to reset.
     - Poison recovery recomputes byte accounting before continuing.

5. **Implement checkpoint compaction and reset semantics**
   - File: `crates/ocean-daemon/src/session_projection.rs`
   - Changes:
     - On committed checkpoint:
       - ignore stale or duplicate persistence revisions;
       - install the complete normalized durable transcript;
       - clear text/thinking/tool transients subsumed by the checkpoint;
       - compact older same-session transcript deltas;
       - retain a checkpoint entry that lets cursors before it advance by replacing state.
     - Expire leases lazily during attach/change operations and periodic registry GC.
     - Prefer evicting entries no active lease still needs, but treat the configured byte limit as hard.
     - Mark a lease reset-required if hard-cap eviction crosses its acknowledged cursor.
   - Acceptance:
     - A slow but valid leased consumer can advance via the retained checkpoint.
     - Expired leases no longer protect history.
     - Epoch mismatch, future cursor, malformed cursor, eviction, and lease mismatch all return explicit reset reasons.
     - No response silently substitutes the current cursor for an invalid one.

6. **Align an attach snapshot with the persisted session checkpoint**
   - Files:
     - `crates/ocean-agent/src/session/mod.rs`
     - `crates/ocean-agent/src/lib.rs`
     - `crates/ocean-daemon/src/session_projection.rs`
   - Changes:
     - Add an `AgentRuntime` method returning normalized session projection input including `persistence_revision`.
     - Read the atomic session file outside the journal mutex.
     - Under the journal mutex:
       - if the journal checkpoint revision equals the file revision, capture runtime state and cursor;
       - if the file revision is newer, install a checkpoint from that snapshot before returning;
       - if the journal revision is newer, release the mutex and retry the file read.
     - Bound retries and return a sanitized internal error rather than an inconsistent snapshot.
   - Acceptance:
     - Returned `snapshot.session.persistence_revision` equals the checkpoint revision represented by its cursor.
     - No filesystem I/O or `.await` occurs while holding the journal mutex.
     - A concurrent atomic rename yields either the complete old checkpoint or complete new checkpoint, never a mixed transcript.

7. **Fold transient session state into the journal**

     - Resolving a permission removes it.
     - Component unmount removes the component.

## Risks

- `context.md` was missing, so approved route names or response terminology may differ from the concrete recommendation above.
- The content journal is process-memory recovery, not a second durable transcript store. Daemon restart changes the epoch and forces reset from session JSON.
- Full checkpoint messages may be large; normalization must omit image base64 and byte accounting must include all retained JSON.
- Journal hard-cap enforcement must override leases; otherwise enough attached clients can make the “256 MiB” bound untrue.
- `updated_ms` must remain backward-compatible but cannot serve as the cursor revision.
- Every successful session-save path, including voice handoff append and session rebinding, must use the revisioned commit helper.
- Transient registry folding has several mutation sites. Missing any permission/request cleanup path would produce stale snapshot state.
- A durable canvas cursor remains underspecified because no canvas retention size, authority, or persistence contract was supplied. This plan therefore enforces strict separation without inventing one.
- No code should touch the accepted Observatory tasks or route content through Observatory under any circumstances.
